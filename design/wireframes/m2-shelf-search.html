W-04 · thread story notes

1Header: title, type badge, state chip, Arc chip, and the ⋯ menu — every M2 action lives here: What Ember knows (O-11), rest, finish, retire, merge, export, delete (O-09). Menu shown open for spec.

2Lazy-load fold: newest page (~50 entries) first, infinite scroll upward; months >12 old rehydrate from cold archive per page (<1s budget) behind an inline "reaching back…" shimmer. Fetch failure → retry affordance, never a blank story.

3Sparks are always the user's verbatim words: serif italic, 2px amber rule (brand §4.3). Voice sparks keep transcript + play chip. Spark ⋯ menu = Move to another thread · Archive spark (hidden from story, still searchable).

4Decisions get the subtle "decided" marker so turning points are scannable; Pebbles render as quiet done milestones — never unchecked debt; done/dissolved only, no "overdue".

5Breadcrumbs: auto-written stop-notes in a distinct hand, neutral dot, labeled immutable. Zero user effort — the app does its own warm starts.

6Past Briefings stay inline as collapsible "you came back here" moments — the story keeps its returns as part of the history.

7Day/era separators use soft time ("Back in March"), never elapsed-day counters (guilt numbers, brand §5.1).

8"Jump to when…" scrubber for long stories — year/era markers double as archive jump points.

W-11 · search notes

1Hybrid query (M2 §8): keyword (exact/fuzzy) + vector similarity + temporal anchoring — "sometime in spring" (or "around when I was into climbing") resolves an era window and time-weights results. Budget: <1.5s at 10k sparks, 20/page.

2Filters requested by F8: type · thread state · time range, plus "include archived" — the archive recovery path (SHELF-04 failure A). Offline: keyword search still works locally; semantic greys out.

3Results grouped by thread; every hit shows why it matched (term, meaning, or era) — inspectable, never spooky. Tap → W-04 scrolled to that spark.

4Loose Sparks surface in results too — low-confidence captures are visible, never hidden (M1 contract), and can be dragged home from here.

5Bulk from results (long-press / shift-click): Move to… · Merge (→ O-08) · Archive · Let rest. Bulk move refiles as one batch training signal with a single undo toast ("Moved 2 sparks to Etsy shop — Undo").

6SHELF-04 no-results: "Nothing surfaced — but nothing is lost." Three recovery offers, never a blank void, no dead-end.

O-08 · merge notes

1Haiku merge assist proposes survivor title + unified type and flags contradictions to this modal rather than resolving them silently (M2 §8).

2Arc-survivor conflict (MODAL-M2-01): when both sources have Arcs, the user picks which survives; the loser pauses — kept in the story, never discarded. Terracotta banner = gentle notice, never red.

3Recovery: sources are tombstoned with pointers; un-merge within 30 days restores both with original stories (sparks added after the merge stay with the survivor, flagged for one-drag re-homing). Digest rebuild queued on confirm.

O-11 · digest notes

1Digest contract (M2 §8): structured — where things stand, key decisions with soft dates, open questions, why-she-cared. Rebuilt by the nightly batch only when the thread changed; marked stale after merges/restores; size-capped (~2k tokens) so briefing context stays bounded.

2Quotes are verbatim-only, rendered in the sacred spark style (serif italic + amber rule). No invented facts; banned-word lint applies to digest text.

3"Correct something" is the whole point: the note is pinned into the next rebuild's input, and briefings prefer user corrections over inferred content (M2 §10) — inspectable + correctable = R3 trust mitigation.

4Panel is read-only otherwise and never deleted while its thread exists; derived data (digest + embeddings) is deletable with the account (M2 §11).
