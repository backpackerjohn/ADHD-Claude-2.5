W-02 · spec notes

1Widget tap lands here already recording — no login wall, no navigation (M1 §7-W1). Surface interactive <200ms cold.

2Live transcript is on-device ASR (default). Auto-stop after 1.5s silence; phone can be pocketed — everything after is async.

3“Never mind” is quiet, not destructive-styled. Drafts persist — no time-outs on input (brand law §9.9).

4Text state: one field, one primary. Mic and moon toggles are secondary; moon auto-offered 23:00–06:00.

5Offline: capture fully works; queued chip is amber-neutral — the only numeric badge allowed anywhere in Ember. Never an error tone (M1 §6).

6ASR failure: audio kept until a transcript exists; retry ladder on-device → server (consented) → “type it”. Still counts as caught (M1 §10).

7Web quick-capture pinned atop sidebar; global C hotkey. A page in the web app, not an extension (R5).

8Catch overlay is 100% system font — no webfont wait inside the <300ms shell (brand §4.1).

W-02c · spec notes

1Toast is a polite live region; it never steals focus and never blocks the next capture (queue never blocks the mic, M1 §6).

2One ember per screen: the Catch button owns the accent; toast uses inverted ink surface (kit §5).

3Deterministic <300ms shell renders before any network round-trip; the thread name arrives ~2–5s later (p90 <5s, M1 §9). Skeleton only if it takes >300ms.

4Week-one conservative mode shifts thresholds up 0.1 while corrections < 10 — early misfiles are the trust-killer (M1 §8).

5Mid-band toast carries the drag affordance inline; tapping opens O-02 correction sheet.

6Low-band copy is canonical (brand §5.2): never “Uncategorized”, “Needs triage”, or “inbox”. 5s Undo lives in every toast.

O-01Filed toast — anatomy

The single most repeated feedback in the product. Every part is load-bearing; the <300ms deterministic shell is the delay-discounting mitigation (R2).

O-01 · anatomy

1Amber spark glyph — the thread’s ember glyph “warms” when the name lands (300ms glow bloom, brand §8).

2Verb is always “Caught” — never “added”, “saved”, “processed” (brand §5.2).

3Thread name in serif italic — same “your world” voice as spark quotes. Honest about the machine: it names where it filed, every time.

4“tap to correct” opens O-02; corrections append to the classifier’s last-30 exemplar block (M1 §8 — corrections as training).

W-12 · spec notes

1Warm framing: “Ember is holding these — 9 sparks”. Count is an ember count, never red, never “inbox” (terminology rule).

2Returning-after-weeks state: one gentle merge offer batch-files everything above threshold in one tap (M1 §6).

3Every card: top-2 thread guess chips (alt_thread_ids ≤2 from the classifier) + “new thread?”. One tap files it and logs a training exemplar (§7-W2).

4Cards are draggable (dashed border, grab cursor) onto the Shelf strip below — the one-drag correction path. Loose sparks never expire, never auto-archive; M5 resurfaces each at most once.

5ASR-fail and offline/AI-outage sparks live here too, with retry and “settling later” chips — nothing is ever silently dropped.

6Visual cap: top 20 + “older sparks” fold, regardless of pile-up size — the tray never becomes a wall (M1 §9, 100× scale).

W-13 · spec notes

1Framing is memory-not-guilt (winner.md #16): “wreckage → memory”. Never “clean up your backlog”.

2Dedupe pre-pass is local & deterministic: normalized-text hash + MinHash near-dupe, in-batch and against the corpus. Re-running the same zip is idempotent — skipped, counted, never doubled (M1 §9–10).

3Deterministic progress numbers, never a bare spinner; pausable/resumable; uploaded files purged from server storage when the batch completes or cancels (M1 §11).

4Cost-cap state: hard $1.50 model spend per ImportBatch on the Batch API (50% off); past cap, leftovers land pre-deduped in “Imported, unsorted” and drain nightly (M1 §8).

W-16 · spec notes

1First-run copy is canonical: “Say anything. Ember will file it.” Cold start is expected — the first 1–3 sparks create proposed threads (M1 §6).

2Mic permission is requested at first voice capture, not at install (M1 §11). No account wall until step 3.

3One-time 3-second toast explainer: “It went to a thread — watch.” Never repeated.

4First auto-created threads are labeled “Ember started this thread — rename or merge anytime” (cold-start exception, M1 §8 guardrails).

5Doorway preview sets the contract: ≤3 items, ≤90 seconds, no list-of-everything (brand law §9.7).

6Notification-window picker: one knock a day max; self-silencing after ignores is disclosed up front (M5 anti-habituation).

7Server-ASR consent is explicit, plain-language, skippable, revocable in Settings; declining just ends the retry ladder at “type it” (M1 §11).

8Skip is a first-class quiet button — consent is never dark-patterned. Total flow: ~90 seconds (day-in-the-life, Day 1).
